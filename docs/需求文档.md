| 项目 | 内容 |
|---|---|
| 版本 | v1.5（含 baseUrl 环境切换 + 模板导出 + 执行引擎 + 测试报告 + 打磨） |

---

## 1. 项目概述

提供对 HTTP 接口测试用例的可视化管理、执行、数据导入导出、测试报告查看与导出的一站式桌面工具。面向测试/开发人员，单机使用，数据全部落在本地。

### 1.1 已确认的技术决策

| 决策点 | 结论 | 说明 |
|---|---|---|
| 数据存储 | 本地 SQLite | 数据库文件存于系统 appdata 目录，支持分页/树查询/事务 |
| HTTP 执行层 | Rust 后端（reqwest） | 性能好、无 CORS 限制、超时可控；前端只负责展示 |
| 批量执行方式 | 串行执行 + 单条超时 | 每条用例可配置超时时间，默认 30s |
| 环境变量/参数化 | 支持 baseUrl 环境切换（见 2.5 模块五）；任意变量参数化（token 等）仍列入后续迭代 | baseUrl 通过本地配置文件指定 |
| UI 语言 | 中文 | 面向国内用户 |

## 2. 功能需求分解

### 2.1 模块一：分组管理（FR-GROUP）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-G1 | 分组支持父子层级（多级树形结构），无层数硬限制（建议界面上限制 ≤ 5 级以防误操作） | P0 |
| FR-G2 | 分组属性：名称、父分组、同级排序号、备注 | P0 |
| FR-G3 | 支持分组的增删改查；删除分组时：若存在子分组或挂接的用例，需提示且默认禁止直接删除（可选"级联删除"需二次确认） | P0 |
| FR-G4 | 分组列表支持简单分页查询（按名称模糊搜索 + 分页） | P1 |
| FR-G5 | 分组可挂接测试用例（一个用例属于一个分组） | P0 |
| FR-G6 | 分组树支持拖拽或按钮方式调整排序与父级（第一版可用"上移/下移/更改父级"按钮实现） | P1 |

### 2.2 模块二：用例导入模板管理（FR-TEMPLATE）

导入模板解决"外部文件字段 → 标准 HTTP 用例字段"的映射问题。

**标准 HTTP 用例字段（映射目标）**：

| 字段 | 说明 | 示例 |
|---|---|---|
| case_name | 用例名称 | 登录成功场景 |
| method | 请求类型 | GET / POST / PUT / DELETE / PATCH |
| content_type | 请求内容类型 | application/json / form-urlencoded / form-data / none |
| url | 请求地址。支持三种写法（见 FR-E2）：①完整绝对地址 `https://api.example.com/login`；②相对路径 `/api/login`（执行时自动拼接当前环境 baseUrl）；③占位符 `{{baseUrl}}/api/login` | /api/login |
| headers | 请求头（JSON 格式） | {"Authorization":"Bearer xxx"} |
| request_body | 请求参数（按 content_type 解析） | {"username":"admin"} |
| query_params | URL 查询参数（JSON） | {"page":1} |
| assert_expr | 响应校验表达式（见 2.3） | jsonpath:$.code == 200 |

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-T1 | 模板属性：模板名称、模板类型（xlsx / json）、字段映射关系集合 | P0 |
| FR-T2 | xlsx 模板：按"中文列标题 ↔ 标准 HTTP 字段名"维护映射，例如「请求地址」→ url | P0 |
| FR-T3 | json 模板：按"结构字段名 ↔ 标准 HTTP 字段名"维护映射，支持嵌套路径（如 data.url → url） | P1 |
| FR-T4 | 映射关系通过表单界面维护：左侧为标准字段列表（必填项标记），右侧选择文件中的对应列/字段 | P0 |
| FR-T5 | 模板支持简单分页查询 + 增删改查 | P0 |
| FR-T6 | 模板内置默认模板：系统预置一套"xlsx-中文标题"通用模板，可复制修改 | P1 |
| FR-T7 | 模板导出：模板列表每条提供「导出模板」按钮，按模板类型（xlsx/json）与字段映射关系，导出一个带表头与示例行的空模板文件到用户选择的本机路径，用户填写后即可按该模板批量导入。xlsx 模板导出 .xlsx（首行为映射的源列名，次行为示例值）；json 模板导出 .json（按映射的源字段路径重建嵌套结构，输出含一条示例对象的数组） | P1 |

### 2.3 模块三：测试用例管理（FR-CASE）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-C1 | 页面布局：左侧分组树（可折叠）+ 右侧用例列表；点击分组节点联动分页查询该分组（含子分组，可选是否递归）下的用例 | P0 |
| FR-C2 | 用例字段：所属分组 + 2.2 节全部标准 HTTP 字段 + 超时时间（默认 30s）+ 备注 | P0 |
| FR-C3 | 用例增删改查；编辑表单按「基本信息 / 请求信息 / 校验表达式」分区展示 | P0 |
| FR-C4 | 批量导入：指定目标分组 + 选择文件（xlsx / json）+ 可主动选择导入模板 → 解析映射后批量入库；导入结果反馈成功/失败条数及失败原因 | P0 |
| FR-C5 | 校验表达式语法（简单规则，非完整 DSL）：见下表 | P0 |
| FR-C6 | 执行方式一：按分组执行（执行所选分组下全部用例，可选含子分组） | P0 |
| FR-C7 | 执行方式二：列表勾选若干用例执行 | P0 |
| FR-C8 | 执行前可输入本次报告名称（默认时间戳，如 `20260827-210401`） | P0 |
| FR-C9 | 用例列表支持简单分页查询 + 名称/URL 模糊搜索 | P0 |
| FR-C10 | 用例编辑时提供"发送试运行"按钮：单发请求并即时展示响应，便于调试（试运行不产生报告记录） | P1 |
| FR-C11 | 用例 URL 支持相对路径 / `{{baseUrl}}` 占位符（语义见 FR-E2）；用例编辑表单中实时展示「按当前环境解析后的完整地址」预览 | P0 |

**校验表达式语法（FR-C5 细化）**：

```
规则格式：<提取器> <比较符> <期望值>    多条规则支持 AND / OR 组合（第一版仅 AND）
```

| 元素 | 支持项 | 示例 |
|---|---|---|
| 提取器 | `status`（HTTP 状态码）、`jsonpath:$.x.y`（响应体 JSON 路径提取）、`header:X-Token`（响应头） | `jsonpath:$.data.id` |
| 比较符 | `==` `!=` `>` `>=` `<` `<=` `contains`（包含字符串） | `==` |
| 动态函数 | 期望值支持 `now()`（当前时间戳）、`len(...)`（对提取值取长度，第一版可先支持 now()） | `status == 200` |

示例：`status == 200 AND jsonpath:$.code == 0 AND jsonpath:$.msg contains 成功`

- 非 JSON 响应体时，`jsonpath` 规则自动跳过并标记该条为「不适用」而非失败。
- 表达式解析失败时在用例保存阶段即报错提示。

### 2.4 模块四：测试报告（FR-REPORT）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-R1 | 每次执行（试运行除外）产生一条执行记录（报告）：报告名称（可输入，默认时间戳）+ 执行总数/成功数/失败数 + 开始时间 + 总耗时 + **执行环境名称及 baseUrl 快照** | P0 |
| FR-R2 | 报告明细：每条用例的请求信息快照 + 实际响应（状态码/响应头/响应体，超长截断存储）+ 每条校验规则的通过/失败/不适用结果 + 单条耗时 + 错误信息 | P0 |
| FR-R3 | 报告列表支持简单分页查询 + 过滤（按报告名称模糊搜索、按执行时间范围、按执行结果成功/失败） | P0 |
| FR-R4 | 报告导出：支持 xlsx 与 json 两种格式导出到用户选择的本机目录 | P0 |
| FR-R5 | 报告查看页：汇总卡片（通过率等）+ 用例结果表格 + 点击行查看完整请求/响应详情 | P0 |
| FR-R6 | 报告删除（单条/批量），删除时提示 | P1 |

### 2.5 模块五：环境配置（baseUrl 动态地址）（FR-ENV）

目标：同一批用例不改数据，通过切换环境即可在不同 baseUrl（如 dev/test/prod）下执行。

**配置文件**：`{appdata}/lever-unit/environments.json`（与数据库同目录，本地可手工编辑），格式示例：

```json
{
  "active": "dev",
  "environments": [
    { "id": "dev",  "name": "开发环境", "baseUrl": "http://192.168.1.10:8080" },
    { "id": "test", "name": "测试环境", "baseUrl": "https://test-api.example.com" },
    { "id": "prod", "name": "生产环境", "baseUrl": "https://api.example.com" }
  ]
}
```

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-E1 | 环境列表通过本地配置文件 `environments.json` 维护；文件不存在时自动创建含 dev/test 两个示例环境的默认文件 | P0 |
| FR-E2 | URL 解析规则（执行与试运行时生效）：①以 `http://` 或 `https://` 开头 → 按原样发送；②相对路径（以 `/` 开头）→ 拼接当前环境 baseUrl；③含 `{{baseUrl}}` 占位符 → 替换为当前环境 baseUrl。当前环境 baseUrl 为空且用例需要拼接时，该条用例判定失败并给出明确错误信息 | P0 |
| FR-E3 | 应用主界面（顶部栏）常驻「当前环境」选择器，切换即时生效，选择持久化到配置文件 `active` 字段 | P0 |
| FR-E4 | 配置文件被外部修改（手工编辑）后，提供「重新加载环境配置」入口；执行前若文件有变化自动重新读取 | P1 |
| FR-E5 | 环境管理小窗：界面上查看/新增/编辑/删除环境并写回配置文件（与手工编辑等价，二选一方式维护均可）；删除当前激活环境需提示并要求先切换 | P1 |
| FR-E6 | 批量执行与试运行均使用当前激活环境；报告记录执行时的环境名与 baseUrl（见 FR-R1），保证历史报告可追溯当时打到哪个环境 | P0 |

## 3. 数据模型（SQLite）

```
groups          分组表：id, name, parent_id(自引用), sort_order, remark, created_at, updated_at
templates       导入模板表：id, name, type(xlsx|json), mappings(JSON文本), is_builtin, created_at, updated_at
test_cases      测试用例表：id, group_id, case_name, method, content_type, url,
                headers(JSON), request_body, query_params(JSON), assert_expr,
                timeout_secs(默认30), remark, created_at, updated_at
reports         测试报告表：id, name, total_count, success_count, fail_count,
                env_name, base_url(执行时快照), started_at, duration_ms, created_at
report_items    报告明细表：id, report_id, case_id(可空,用例可能已删), case_name,
                method, url(解析后的完整请求地址快照), request_snapshot(JSON), response_status, response_headers(JSON),
                response_body(截断), assert_results(JSON), is_success, error_msg, duration_ms

（环境配置不落库：由 {appdata}/lever-unit/environments.json 文件承载，见 2.5）
```

约束：全部软外键由应用层维护；report_items 保留请求/响应快照，用例删除不影响历史报告。

## 4. 非功能需求

| 编号 | 需求 |
|---|---|
| NFR-1 | 分页默认 20 条/页，可选 10/20/50/100；分组树 + 列表在万级用例量下交互不卡顿 |
| NFR-2 | HTTP 执行使用 Rust reqwest，忽略系统代理可配置（第一版默认不忽略）；单条超时可配置 |
| NFR-3 | 数据库文件位置：`{appdata}/lever-unit/lever-unit.db`，提供"打开数据目录"入口（P1） |
| NFR-4 | 导入事务性：单次导入要么全部成功、要么全部回滚（或失败条目跳过并明确反馈，二选一：**采用跳过失败+汇总反馈**，避免一条坏数据阻断整批） |
| NFR-5 | 界面异常（网络超时、表达式错误等）均有明确中文提示，不白屏 |

## 5. 明确不做（第一版边界）

- ~~环境变量/参数化~~ → **baseUrl 环境切换已纳入 v1.1（模块五）**；任意变量参数化（token、自定义变量等）仍不做 → 迭代二
- 用例并发执行 → 迭代二
- 校验规则 OR 组合、前后置脚本（如提取变量传递到下一条用例）→ 迭代三
- 多用户/远程同步/云存储
- 非 HTTP 协议（WebSocket、gRPC 等）
- 环境配置的云端同步 / 团队共享（本地文件已满足单机需求）

## 6. 迭代路线（概要，详见编码计划）

1. **M1 骨架与数据层**：SQLite 建库、Rust 命令层、前端路由与布局、环境配置文件加载与默认文件生成
2. **M2 分组管理**：分组树 + CRUD
3. **M3 用例管理**：用例 CRUD + 左树右表联动 + URL 相对路径/占位符编辑与解析预览
4. **M4 导入模板 + 批量导入**
5. **M5 执行引擎 + 校验表达式**（执行时按当前环境解析 baseUrl，报告记录环境快照）
6. **M6 测试报告 + 导出**
7. **M7 打磨与打包**（含环境管理小窗）
