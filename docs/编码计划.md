# LeverUnit 编码计划（按里程碑分阶段）

> 依据：`docs/需求文档.md` v1.6（含 baseUrl 环境切换 + 模板导出 + 执行引擎 + 测试报告 + 环境通用请求头 + 用例批量导出/导入 JSON）
> 约定：每个里程碑完成即「可运行、可演示」，Rust 命令统一走 `#[tauri::command]`，前端统一封装 `src/api/` 调用层。
> 通用规范（M3 起约定）：所有 Input struct 字段命名 **snake_case** + `#[serde(deny_unknown_fields)]`，并配套反序列化单元测试。

---

## M1 项目骨架与数据层（地基）

**目标**：跑通「前端 → Tauri command → SQLite → 返回」全链路。

### 任务
1. Rust 依赖引入：`rusqlite`（bundled，免装 SQLite）、`serde`/`serde_json`、`reqwest`（后续用）、`calamine`（xlsx 解析，M4 用，可后引）
2. 数据库初始化模块 `src-tauri/src/db.rs`
   - 启动时打开 `{appdata}/lever-unit/lever-unit.db`（目录自动创建）
   - 建表 SQL 集中在 `migrations.rs`，含 groups/templates/test_cases/reports/report_items 五表 + 索引
3. 通用返回结构：`ApiResult<T>`（code/msg/data），分页结构 `PageResult<T>`
4. 前端基础建设
   - 安装 `react-router-dom`、UI 库（Ant Design 5，中文生态贴合后台管理风格）
   - 布局：左侧导航（分组管理/导入模板/测试用例/测试报告）+ 内容区 + **顶部栏环境选择器**
   - `src/api/` 封装 invoke 调用；`src/types/` 存放 TS 类型（与 Rust 结构体一一对应）
5. 环境配置模块 `src-tauri/src/env_config.rs`（FR-E1~E3）
   - 启动时读取 `{appdata}/lever-unit/environments.json`，不存在则生成默认文件（dev/test 两个示例环境）
   - 命令：`env_list / env_switch / env_reload`（FR-E5 的界面编辑放 M7，本阶段先支持手工编辑 + 重载）
   - 前端顶部栏：环境下拉选择，切换即调 `env_switch` 持久化 `active`
   - URL 解析函数 `resolve_url(url, base_url)` 纯函数 + 单元测试（绝对/相对/占位符三种规则，供 M3 预览与 M5 执行共用）
6. 冒烟验证：临时 command `ping_db()` 返回数据库版本，前端页面展示

**产出**：可启动的空壳应用 + 五张表 + 前后端类型对齐 + 环境配置读写与切换。

## M2 分组管理（FR-G1~G6）

1. Rust 命令：`group_create / group_update / group_delete / group_page / group_tree`
   - `group_tree` 一次查全量内存组树（万级内无压力），前端懒展开
   - 删除校验：存在子分组或用例时返回错误；支持 `force` 参数级联删（前端二次确认后传）
   - `group_update` 支持改名称/父级/排序（防环校验：父级不能是自己或自己的子孙）
2. 前端页面「分组管理」：
   - 左侧树 + 右侧表格双区；或纯表格 + 父级列。采用**左树右表**
   - 新增/编辑弹窗（名称、父级下拉树、排序号、备注）
   - 分页查询 + 名称模糊搜索
3. 单元测试：`group_update` 的防环逻辑

**验收**：能建出 3 级分组、改名、调整排序、删除被拦截/级联删除均正常。

## M3 测试用例管理（FR-C1~C3、C9）

1. Rust 命令：`case_create / case_update / case_delete / case_page`
   - `case_page` 参数：group_id（可空=全部）、recursive（是否含子分组，由 Rust 递归收集 group_id 集合后 `IN` 查询）、关键字、分页
2. 前端页面「测试用例」：
   - 左侧分组树（复用 M2 组件，带"全部用例"根节点）+ 右侧用例表格
   - 用例编辑抽屉（Drawer，按需求分区：基本信息 / 请求信息[方法、URL、content_type、query、headers、body] / 校验表达式 / 备注）
   - URL 输入框：支持相对路径与 `{{baseUrl}}` 占位符，下方实时显示「按当前环境解析后的完整地址」预览（FR-C11，调 Rust 端 `resolve_url`）
   - 校验表达式编辑：第一版用**多行文本 + 语法说明折叠面板**，保存时调用 Rust 端 `assert_expr_validate` 校验
   - 表格列：名称、方法（彩色 Tag）、URL、所属分组、更新时间、操作
3. 类型校验：method 枚举、URL 格式（允许相对路径与占位符）、headers/query_params 为合法 JSON

**验收**：左树点分组联动过滤；增删改查、分页、搜索全通；非法表达式保存时报错；切换环境后 URL 解析预览实时变化。

## M4 导入模板 + 批量导入（FR-T1~T7、FR-C4）

1. 依赖引入：`calamine`（xlsx 解析）、`serde_json`（json 文件）、`rust_xlsxwriter`（xlsx 写出，导出模板/报告共用）
2. Rust 命令：
   - `template_create / template_update / template_delete / template_copy / template_page`
   - `template_export(template_id, file_path)`（FR-T7）→ 按模板类型与字段映射导出可填写的模板文件：xlsx 首行为映射源列名、次行为示例值；json 按源字段路径重建嵌套结构导出含一条示例对象的数组
   - `import_preview(file_path, template_id)` → 返回解析后的用例数组预览（含错误行标注），**不落库**
   - `import_commit(group_id, cases)` → 批量插入，跳过非法条目并返回 `{success_count, failed: [{row, reason}]}`
3. 前端页面「导入模板」：
   - 模板列表（分页）+ 编辑表单：模板类型切换（xlsx/json）
   - 映射关系维护表：每行 = 标准字段（固定，必填星标）↔ 文件列名（xlsx 填中文标题 / json 填字段路径）；支持「从文件读取列头」辅助按钮（选文件后自动填充候选列）
   - 内置默认 xlsx 模板（is_builtin，不可删只能复制）
   - **模板列表每行操作统一收进「操作」下拉**：编辑 / 复制 / **导出模板** / 删除（内置删除禁用以防误删）；「导出模板」调保存对话框选路径 → 调 `template_export`
4. 前端「批量导入」向导（用例页工具栏入口）：选分组 → 选模板 → 选文件 → 预览确认 → 提交 → 结果反馈

**验收**：用示例 xlsx/json 各导一次 10 条数据（含 2 条故意非法），结果 8 成功 2 失败且原因明确；对任一模板点「导出模板」后，xlsx 用 Excel 打开表头正确、json 可被解析且含示例对象。

## M5 执行引擎 + 校验（FR-C5~C8、FR-C10、FR-E2/E6）✅ 已完成

1. Rust 模块 `executor.rs`（实现要点）：
   - `run_cases(case_ids, report_name)` 命令（异步）：串行执行，逐条构造请求（method/url/query/headers/body 按 content_type 组装，含 multipart/form-data）→ reqwest 发送（单条 timeout）→ 采集响应 → 校验 → 写 report + report_items → 返回报告 id
   - **执行前重新读取环境配置（FR-E4），用当前激活环境 baseUrl 解析每条用例 URL**（复用 `env_config::resolve_url`）；需要拼接但 baseUrl 为空的用例直接记失败并写明原因
   - **报告记录执行环境快照（env_name + base_url，FR-E6）**；report_items 的 url 存解析后的完整地址；响应体截断 64KB
   - 执行过程通过 Tauri event（`run-progress`）向前端推送进度（current/total、用例名、phase、verdict、detail）
   - `try_run(input)` 命令：单条试运行，按当前环境解析 URL，发送但不落库
2. 校验模块 `assert_expr.rs`（在 M3 解析基础上补充求值）：
   - `eval(rule, status, body, headers)`：提取器 `status` / `jsonpath:$.x.y`（手写简化版，支持 `$.a.b[0].c`）/ `header:X`
   - 比较符：== != > >= < <= contains；数值与字符串自动判型
   - 动态函数：`now()`（当前 Unix 秒）；`len(...)` 语法允许但未在求值中特殊处理
   - 结果分级：通过 / 失败 / 不适用（非 JSON 响应体遇到 jsonpath 规则）
   - `case_ids_by_group(group_id, recursive)` 命令：批量取分组下用例 id（执行前用）
3. 单元测试：表达式解析 + 各种比较符 + jsonpath 提取 + skipped 分支 + now()
4. 前端：
   - 用例页：「执行本分组 / 执行全部」「执行选中（勾选）」入口 → `RunDialog`（报告名默认时间戳、实时进度表、完成汇总、报告 id 提示）
   - 用例编辑抽屉「发送试运行」→ `try_run` → 结果弹窗（解析后地址/状态码/响应头/响应体/校验结果表）

**验收（建议手测）**：对公开测试接口（如 httpbin）执行 3 条用例（成功/校验失败/超时），进度实时、报告落库、试运行不产生报告；同一批用例切换 dev/test 两个环境各执行一次，请求实际打到不同 baseUrl 且两份报告的环境快照正确。

## M8 环境通用请求头 + 超时默认调整 + 导入规则增强（FR-E7、FR-C2、FR-C4）✅ 已完成（2026-08-31）

**目标**：环境维度的公共请求头在执行链路自动生效；超时不填默认 10s；模板导入的过滤与自动命名规则落地。

### 任务

1. **环境通用请求头（FR-E7）— 后端 `env_config.rs`**
   - `EnvItem` 新增 `common_headers: Vec<CommonHeader>`（`CommonHeader { key, value }`），`#[serde(default)]` 兼容旧 environments.json（缺字段=空列表），保存时自动补全字段
   - 新增纯函数 `merge_headers(case_headers: &Map, env_headers: &[CommonHeader]) -> Map`：环境头先入、用例头后入覆盖同名 key；**单元测试覆盖**：双方均空 / 仅环境 / 仅用例 / 同名覆盖 / 多 key 合并
   - `executor.rs`：`run_cases` 与 `try_run` 在构造请求时，从当前激活环境取 common_headers 调用 `merge_headers`；**合并后的最终请求头写入 report_items.request_snapshot**（试运行直接返回给前端展示，便于确认合并结果）
2. **环境通用请求头 — 前端 `EnvManager.tsx`**
   - 环境编辑区新增「通用请求头」key-value 可编辑表格（Antd 可增删行的 Table/数组表单）：行内输入 key/value、支持随时添加/删除行、key 重复即时提示；「保存」走既有 `env_save` 整体写回
   - 顶栏环境切换器 tooltip 展示当前环境通用请求头条数，提示执行时自动合并
3. **超时默认 30s → 10s（FR-C2）— `cases.rs` / `migrations.rs` / 前端**
   - `case_create` / `case_update` / `try_run` 中 `unwrap_or(30)` 统一改为 `unwrap_or(10)`；建表 SQL 列默认值改 `DEFAULT 10`（对既有库不重建，新库生效；**存量行已保存的 30 保留**）
   - 前端用例编辑抽屉：超时时间改为**可清空**（InputNumber allowClear / 空值占位提示「不填默认 10 秒」）；列表超时列空值显示「10(默认)」
   - 导入模板示例值 `"timeout_secs" => "30"` 同步改为空（走默认）
4. **导入规则增强（FR-C4）— `import.rs`**
   - `import_preview` / `import_commit`：url 为空的行从「失败」改为「**忽略**」，结果结构增加 `ignored_count`（及行号列表），前端预览与结果反馈区分「成功 / 忽略（请求地址为空）/ 失败」
   - case_name 为空时：由 `(第N条)` 改为 **`{分组名}_{序号}`** 自动生成——序号 = 目标分组现有用例数 + 本次导入内序号（连续递增）；获取分组名需在 commit 内查询一次分组（不存在则报错）
   - 单元测试：url 空行被忽略、名称自动生成序号连续、`ignored_count` 统计正确
5. 回归：`cargo test` + `npm run build` 双轨验证

**产出**：环境头在批量执行/试运行自动合并且报告可追溯；新用例不填超时即 10s；模板导入忽略空 url 行并自动命名。

**验收**：① dev 环境配 `Authorization` 头，执行含同名/不含同名头的用例各一，报告快照中合并结果正确（用例覆盖环境）；② 新建用例不填超时执行，超时报错提示 10s；③ 导入 10 条（3 条 url 空、2 条名称空）→ 7 成功、忽略 3 条，空名称行显示 `分组名_5` 之类自动名。

## M9 测试用例批量导出/导入（固定 JSON）（FR-C12、FR-C13）✅ 已完成（2026-08-31）

**目标**：不依赖导入模板，用系统固定 JSON 格式在任意分组/用例范围内快速搬运用例。

**验收**：某分组（含子分组共 12 条）导出 → 新建空分组导入 → 条数一致、字段一致、名称为空的行被自动命名；导入的文件被手工破坏 format 字段时给出明确中文报错。

## 风险与对策

| 风险 | 对策 |
|---|---|
| jsonpath 完整实现复杂 | 第一版支持 `$.a.b[0].c` 常用语法即可，明确不支持过滤器/递归 |
| xlsx 中文列头兼容（合并单元格等） | 预览机制 + 失败行明确反馈，不让用户盲导 |
| report_items 响应体过大 | 存储截断（如 64KB），详情标注"已截断" |
| 串行执行慢 | 已确认接受；进度实时展示缓解等待焦虑；并发留到迭代二 |
| baseUrl 拼接边界（尾斜杠、相对路径多级） | `resolve_url` 纯函数集中处理 + 单元测试覆盖（`/api` × `http://x:8080/` 等组合），避免散落各处的字符串拼接 |
